# kwxFFI tests

Two ways in, both driven from the repository root unless noted.

## Without a CMake build

```sh
python tests/run_checks.py --static
```

`--static` runs only the checks that read the source tree. Without the flag the
export snapshot and the `deno check` wrapper run too, using the newest `kwxgen`
binary found under `bin/` or `build/` (override with `--kwxgen <path>`). Each
check prints one `PASS`, `FAIL`, or `SKIP` line plus a summary; the exit code is
1 only when a check failed. A checker script that does not exist yet reports
`SKIP (not implemented yet)`.

## With CMake and CTest

From `tests/`:

```sh
cmake --preset default
ctest --preset cheap
```

Or equivalently, from the repository root:

```sh
cmake -S tests -B build/tests -G "Ninja Multi-Config"
cmake --build build/tests --config Release
ctest --test-dir build/tests -C Release --output-on-failure
```

The tests project pulls in `kwxgen`, builds `kwxgen_core` from the generator
sources, and registers every check with the `cheap` label.

## What the checks mean

- `guard_lint` — scans `include/*.h` for declarations wrapped in platform
  guards (`__WINDOWS__`, `_WIN32`, `__APPLE__`, `__WXMSW__`, `wxHAS_*`, ...).
  The generator cannot see guards, so a guarded declaration produces bindings
  that only link on one platform. Feature guards (`wxUSE_GUI` and friends) are
  reported as notes, not errors.
- `guard_parity` — compares the guard state of each header declaration against
  its definition in `src/*.cpp` and reports declarations with no definition.
- `export_snapshot` — regenerates the export manifest with `kwxgen exports`,
  cross-checks the `.def`/`.map`/`.exp` writers, and compares a count+sha256
  digest with `tests/expected/symbols.sha256`. `kwxgen exports` always emits the
  complete surface regardless of profile, so the digest covers every symbol the
  library ships. Run `kwxgen generate` and `kwxgen verify` with the same
  `--profile`; the two must agree or `verify` reports the profile-filtered
  symbols as missing.
- `symbol_resolve` — loads the built shared library and resolves every symbol
  generated by `kwxgen exports` (registered only for shared-library builds).
- `checker_self_test` — runs both guard checkers against
  `tests/fixtures/lint_tree` and fails when an expected finding is missing or a
  severity changed. This pins the multi-line declaration detector.
- `deno_check` — runs `kwxgen check`; exits 77 (CTest `SKIP`) when `deno` is not
  installed.
- `parser_tests` — assert-based tests for the kwxgen parsers and the export
  symbol collector.

## Triage a digest mismatch

`export_snapshot` compares the symbol set generated by `kwxgen exports` with the
count and sha256 recorded in `tests/expected/symbols.sha256`. A mismatch means
the exported FFI surface changed, not that the test is flaky. Find the change
before touching the baseline:

```sh
git worktree add ../kwxFFI-base <merge-base>
python tests/checks/export_snapshot.py --root ../kwxFFI-base --kwxgen <kwxgen> --write-list /tmp/base-symbols.txt
diff -u /tmp/base-symbols.txt build/tests/exports/symbols.generated.txt
```

The failing run already wrote the current sorted list to
`build/tests/exports/symbols.generated.txt`, so the diff shows exactly which
symbols were added or removed. Regenerate the baseline with `--update` only
when the surface change is intended.

## Expected state

The suite is expected to be green. A `guard_lint` or `guard_parity` error is a
real defect: do not weaken the checks or add allowlist entries to hide it. A
digest mismatch means the FFI surface changed; triage it as described above.
